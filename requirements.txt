# MF Facts RAG — dependency set. The MF_RAG_-prefixed .env keys are NOT here; see .env.example.
#
# ── Pinning policy ─────────────────────────────────────────────────────────────
# Every direct dependency is pinned with `==` to the exact versions installed and
# proven in the local environment. The earlier `>=` pins let Render's build
# resolve newer releases (chromadb 1.6+ changed PersistentClient's internals and
# crashed the app with `KeyError: <chroma path>` at startup), so do not relax a
# pin without re-verifying the full pipeline (274 tests).
#
# ── Installing in three steps ──────────────────────────────────────────────────
# Stages 1-2 (loading, chunking) need only the "light" block below. Install that first:
#     pip install -r requirements-light.txt
#
# Stage 3 needs torch. The default Windows wheel is a ~2.5 GB CUDA build that this project
# never uses — it embeds 107 chunks on CPU in ~10 s. Install the CPU wheel instead:
#     pip install torch --index-url https://download.pytorch.org/whl/cpu
# That is ~200 MB and is what was actually used to build the committed index.
#
# Then:
#     pip install -r requirements.txt
#
# torch stays `>=` on purpose: the `+cpu` local tag can only be pinned with the
# CPU index active (see render.yaml's Build Command), and it is installed there
# first, so this line is always already satisfied.

# ── STAGE 1 · loading ────────────────────────────────────────────────────────
httpx==0.28.1
beautifulsoup4==4.15.0
trafilatura==2.2.0

# ── STAGE 2 · chunking ───────────────────────────────────────────────────────
langchain-text-splitters==1.1.2

# ── STAGE 3 · embedding ──────────────────────────────────────────────────────
# torch is installed separately, from the CPU index — see the header.
#
# The model is `sentence-transformers/all-MiniLM-L6-v2` (a HuggingFace repo name), but the
# `sentence-transformers` *package* is deliberately not used. Its top-level __init__ eagerly
# imports an evaluation module that needs scikit-learn, and on a machine where Windows
# Application Control blocks sklearn's compiled extensions that import fails outright.
# embedder.py instead does what the package does for this model: tokenize, run the BERT
# encoder, attention-mask mean pooling, L2 normalise — reading the recipe from the model
# repo's own 1_Pooling/config.json and asserting it matches, so it is never assumed.
#
# transformers is pinned <5 because 5.x imports scikit-learn unconditionally from its
# generation module, which blocks `import transformers` itself on such a machine. 4.46.3 is
# the version that treats scikit-learn as the optional dependency it is.
torch>=2.0            # install from the CPU index, see header
transformers==4.46.3
tokenizers==0.20.3
